Question 1BasicYour company must make sure nobody can create Azure resources outside Central India and South India, including subscription Owners. What do you use?

The answer is B

Azure Policy evaluates every create and update request that passes through Azure Resource Manager. The built-in Allowed locations policy with the Deny effect rejects any resource whose region isn't on the list, whoever makes the request. RBAC decides who can act; Policy decides what is allowed. Assigning the policy at a management group makes every current and future subscription inherit it.

Every option, explained

  • A. Not this. RBAC roles can't be limited by region. They grant actions on scopes (management group, subscription, resource group), not locations.
  • B. Correct. Policy checks every create request against the rule, whoever sends it, so even an Owner is refused.
  • C. Not this. A ReadOnly lock blocks all changes, including in allowed regions. Locks don't understand locations.
  • D. Not this. A management group only organises subscriptions. It enforces nothing until you assign a policy to it.

Keywords that point to it: "must make sure""outside""including Owners"

Question 2BasicA production virtual network was deleted by mistake last month. Engineers must still be able to change its settings, but nobody should be able to delete it. What do you apply?

The answer is A

Resource locks protect against accidents. CanNotDelete allows reads and changes but blocks deletion; ReadOnly blocks deletion and changes (and some operations that look like reads, such as listing storage keys). Locks apply to everyone, including Owners, until someone with permission removes the lock, so they stop mistakes rather than determined attackers.

Every option, explained

  • A. Correct. Users can still read and modify the resource, but not delete it, even with the Owner role, until the lock is removed.
  • B. Not this. ReadOnly also blocks changes, such as adding a subnet. The engineers would be stuck.
  • C. Not this. Reader removes the ability to change settings too, and Owners outside the team could still delete it.
  • D. Not this. Audit only reports. It never blocks anything, including a delete.

Keywords that point to it: "by mistake""still be able to change""nobody should be able to delete"

Revise: Module 02 · Governance →

Question 3BasicA web app on App Service must read secrets from Key Vault. Security says there must be no passwords or keys stored in the app's configuration. What do you use?

The answer is A

A managed identity is an identity in Entra ID that Azure manages for a resource. The app requests a token from a local endpoint; Azure handles the credentials and rotation. Grant it the least-privilege role (here, Key Vault Secrets User on that vault) and the app can read secrets with no stored secret anywhere. Use system-assigned for one resource, user-assigned when several resources share one identity.

Every option, explained

  • A. Correct. Azure creates and rotates the identity's credentials itself; the app asks for a token at run time and stores nothing.
  • B. Not this. That's exactly a secret stored in configuration, and it expires and must be rotated by hand.
  • C. Not this. SAS tokens are for Storage, not Key Vault, and a token is still a secret you'd have to store.
  • D. Not this. Key Vault has no admin password, and sharing any human's credentials breaks the 'no passwords' rule.

Keywords that point to it: "no passwords or keys stored""App Service""Key Vault"

Question 4BasicYou have 40 subscriptions. Twelve are production, and you want one set of policies and role assignments to apply to all production subscriptions, including ones created later. What do you use?

The answer is C

Management groups sit above subscriptions in the hierarchy (up to six levels below the root). Policy and RBAC assignments made on a management group are inherited by every subscription and resource underneath. Move a new subscription under the production group and it gets the same guardrails immediately. That's the basis of the landing zone hierarchy.

Every option, explained

  • A. Not this. Resource groups live inside a single subscription. They can't group subscriptions.
  • B. Not this. Tags label resources for cost and filtering. Policies and role assignments aren't inherited through tags.
  • C. Correct. Everything assigned to a management group flows down to every subscription under it, now and in the future.
  • D. Not this. Works on day one, but drifts as soon as someone forgets to run it for a new subscription.

Keywords that point to it: "40 subscriptions""apply to all""including ones created later"

Question 5CoreAdministrators should hold the Owner role only when they need it: they request it, a manager approves it, and it expires after four hours. What do you use?

The answer is D

Privileged Identity Management turns standing admin rights into eligible assignments. When needed, the admin activates the role, optionally with justification, MFA and approval, for a set duration, then it expires automatically. Every activation is audited. PIM needs Entra ID P2 (or Entra ID Governance). Pair it with access reviews to check who is still eligible.

Every option, explained

  • A. Not this. Conditional Access controls how someone signs in (MFA, device, location). It doesn't grant or expire roles.
  • B. Not this. Access reviews periodically ask whether existing access is still needed. They don't give time-limited elevation on request.
  • C. Not this. A smaller role is still permanent. The requirement is 'only when needed', not 'less'.
  • D. Correct. PIM makes users eligible for a role, then activates it on request, with approval, MFA and an expiry time.

Keywords that point to it: "only when they need it""approves""expires"

Question 6CoreEmployees of a partner company need to sign in to one of your internal apps using their own company accounts. You don't want to manage their passwords. What do you use?

The answer is D

B2B collaboration invites users from another organisation as guests. They authenticate with their own identity provider (their Entra tenant, a Google account and so on), and your tenant decides their permissions. When their company disables them, they lose access to you as well. Use access reviews to clean up guests regularly.

Every option, explained

  • A. Not this. You'd manage their passwords and leavers yourself, which is exactly what you want to avoid.
  • B. Not this. External ID is built for consumers who sign themselves up, not for staff of a partner organisation.
  • C. Not this. Entra Connect syncs your own on-premises directory, not another company's.
  • D. Correct. Guests sign in with their home organisation's account; you control what they can access in your tenant.

Keywords that point to it: "partner company""their own company accounts""don't want to manage their passwords"

Question 7CoreUsers must use MFA when signing in from outside the corporate network, but not when they're in the office. What do you configure?

The answer is C

Conditional Access is Entra ID's if-then engine: if a sign-in matches conditions (user, app, location, device, risk) then grant, block or require controls such as MFA. Define the office's public IP ranges as a named location and exclude it from the MFA policy. It needs Entra ID P1. Security defaults are a free baseline, but they can't express conditions like this.

Every option, explained

  • A. Not this. Security defaults switch on MFA prompts across the tenant with no location rules. You can't fine-tune them.
  • B. Not this. NSGs filter network traffic to Azure resources. They have nothing to do with sign-in.
  • C. Correct. Conditional Access uses signals such as location to decide when to ask for MFA. Named locations define the office IPs.
  • D. Not this. Legacy per-user MFA always asks; it can't tell office from outside.

Keywords that point to it: "outside the corporate network""not when they're in the office"

Question 8IntermediateA checkout depends on an App Service web app (SLA 99.95%) and an Azure SQL database (SLA 99.99%). Both must work for checkout to work. What is the composite SLA?

The answer is B

When components are in series (all must work), the composite SLA is the product: 99.95% × 99.99% ≈ 99.94%, which allows roughly 26 minutes of downtime a month compared with about 22 for the web app alone. To raise a composite SLA you add redundancy (parallel paths, such as a second region), since for parallel copies the combined availability is 1 − (1 − A)2.

Every option, explained

  • A. Not this. That's only the database. A chain can never be more available than its weakest link.
  • B. Correct. Multiply the SLAs of services that must all work: 0.9995 × 0.9999 = 0.9994, so about 99.94%.
  • C. Not this. That's the web app alone. Adding another required component can only lower the total.
  • D. Not this. Averaging SLAs isn't valid. For dependencies in a chain, you multiply.

Keywords that point to it: "both must work""composite SLA"

Question 9IntermediateYou need to collect performance counters and Windows event logs from 200 VMs into a Log Analytics workspace, choosing exactly which events are collected. What do you use?

The answer is B

The Azure Monitor Agent (AMA) collects data from inside VMs (and Arc-enabled servers). What it collects is described in data collection rules: counters, event logs with XPath filters, destinations. One DCR can apply to many machines, and you can assign them with Azure Policy at scale. Filtering at collection time also lowers ingestion cost.

Every option, explained

  • A. Not this. The Log Analytics agent was retired in August 2024. New designs use the Azure Monitor Agent.
  • B. Correct. The agent collects guest data; DCRs define what to collect, filter it, and say which workspace receives it.
  • C. Not this. Diagnostic settings send Azure platform metrics and resource logs, not the guest operating system's events and counters.
  • D. Not this. The Activity log records control-plane operations on Azure resources, not what happens inside the VM.

Keywords that point to it: "performance counters""Windows event logs""choosing exactly which"

Question 10IntermediateEvery new resource in your landing zone must automatically send its resource logs to a central Log Analytics workspace, even if the team that creates it forgets. What do you use?

The answer is C

Resource logs are off until a diagnostic setting sends them somewhere. A policy with the DeployIfNotExists effect checks each resource and deploys the setting when it's missing, using a managed identity. New resources are fixed as they're created; existing ones need a remediation task. Azure provides built-in initiatives for this, so you rarely write them yourself.

Every option, explained

  • A. Not this. Relies on people remembering, which is the problem you're trying to solve.
  • B. Not this. The agent runs inside VMs. PaaS resources such as Key Vault or SQL send logs through diagnostic settings, not an agent.
  • C. Correct. The policy adds the missing diagnostic setting automatically; a remediation task fixes resources that already exist.
  • D. Not this. Useful, but the Activity log covers control-plane events, not each resource's own logs (for example Key Vault access).

Keywords that point to it: "automatically""even if the team forgets""central"

Question 1BasicAn online shop stores millions of product images that browsers load over HTTPS. Which storage service fits?

The answer is C

Blob Storage is Azure's object storage: unlimited unstructured data (images, video, backups, logs), addressed by URL and served over HTTPS. It has access tiers for cost, lifecycle rules, and integrates with Front Door or a CDN for global delivery. When the brief says files read by browsers or apps over HTTP, think Blob first.

Every option, explained

  • A. Not this. Azure Files gives SMB and NFS shares for servers and users, not cheap objects served to browsers at scale.
  • B. Not this. Disks attach to one VM. Browsers can't read from them directly.
  • C. Correct. Object storage for unstructured files at massive scale, reachable over HTTPS and easy to put behind a CDN.
  • D. Not this. Table Storage holds small structured entities, not image files.

Keywords that point to it: "millions of""images""over HTTPS"

Question 2BasicA legacy Windows application expects a network drive (SMB share) mounted on several VMs in Azure and on servers in the office. Which service fits with the least change?

The answer is C

Azure Files provides managed SMB (and NFS) shares. Windows mounts them like any network drive, so lift-and-shift apps work unchanged. It supports identity-based access with AD DS or Entra Kerberos, snapshots, Azure Backup, and Azure File Sync to cache shares on local servers.

Every option, explained

  • A. Not this. The app expects a mapped SMB drive. Blob needs code that speaks the Blob API, or extra tools.
  • B. Not this. Shared disks need cluster software, and on-premises servers can't attach them.
  • C. Correct. Fully managed SMB file shares that Windows can mount as a drive, from Azure or on-premises.
  • D. Not this. Queues pass messages between components. They don't store files.

Keywords that point to it: "network drive""SMB share""least change"

Revise: Module 05 · Data Storage →

Question 3BasicData in a storage account must stay available if one datacentre (availability zone) in the region fails. A copy in another region isn't needed. Which redundancy option fits at the lowest cost?

The answer is A

Match redundancy to the failure you must survive. LRS covers a disk or rack failure. ZRS covers a datacentre (zone) failure. GRS / GZRS add a copy in the paired region for a regional disaster, and the RA- versions let you read that copy at any time. The requirement says zone failure and no second region, so ZRS.

Every option, explained

  • A. Correct. ZRS writes copies synchronously across three availability zones, so losing one zone doesn't interrupt access.
  • B. Not this. LRS keeps three copies in a single datacentre. If that datacentre fails, the data is unavailable.
  • C. Not this. GRS's primary copy is LRS in one datacentre, plus an asynchronous copy in another region. It costs more and doesn't keep you running through a zone failure without a failover.
  • D. Not this. It would survive a zone failure, but it adds a second region you said you don't need, at a higher price.

Keywords that point to it: "one datacentre""isn't needed""lowest cost"

Revise: Module 05 · Data Storage →

Question 4BasicAudit files must be kept for 7 years. They're almost never read, and when they are, waiting several hours is acceptable. Which blob access tier is cheapest?

The answer is A

Tiers trade storage price against access price and speed: Hot → Cool (30-day minimum) → Cold (90 days) → Archive (180 days). Archive is offline: you rehydrate a blob to an online tier before reading it, which takes hours. 'Almost never read' plus 'waiting hours is fine' is the textbook Archive case. Use a lifecycle rule to move files there automatically.

Every option, explained

  • A. Correct. The lowest storage price. Data is offline and must be rehydrated (up to about 15 hours) before reading.
  • B. Not this. Hot has the highest storage price. It's for data read often.
  • C. Not this. Cheaper than Hot, but meant for data read occasionally (at least 30 days). Archive is far cheaper for data almost never read.
  • D. Not this. Cheaper than Cool and still online, but Archive is cheaper still when an hours-long wait is acceptable.

Keywords that point to it: "7 years""almost never read""several hours is acceptable"

Question 5CoreA storage account must survive a full regional outage, and the application must be able to read the data from the second region at any time, without waiting for a failover. Which option fits?

The answer is D

RA-GRS (and RA-GZRS, which also spreads the primary across zones) adds a read-only -secondary endpoint in the paired region. Apps can read from it during an outage without waiting for a failover. Replication is asynchronous, so the secondary may be slightly behind; check the Last Sync Time property if that matters.

Every option, explained

  • A. Not this. GRS keeps a copy in the paired region, but you can't read it until a failover happens.
  • B. Not this. ZRS stays in one region, so a regional outage takes it down.
  • C. Not this. Up to a day of data could be lost, and you'd have to build and run the copying yourself.
  • D. Correct. Read-access geo-redundant storage keeps a copy in the paired region and exposes a secondary endpoint that can be read at any time.

Keywords that point to it: "regional outage""read the data from the second region at any time""without waiting for a failover"

Question 6CoreYou're moving SQL Server databases that use SQL Agent jobs and cross-database queries. You want a managed (PaaS) service with as few code changes as possible. What do you choose?

The answer is A

SQL Managed Instance is the lift-and-shift PaaS target for SQL Server. It keeps instance-scoped features (SQL Agent, cross-database queries, Database Mail, CLR, linked servers) while Microsoft handles patching, backups and high availability. Choose a VM only when you need OS access or an unsupported feature; choose SQL Database for new cloud-first apps.

Every option, explained

  • A. Correct. A managed SQL Server instance with near-complete compatibility, including SQL Agent and cross-database queries.
  • B. Not this. Single databases don't support SQL Agent or cross-database queries the way an instance does.
  • C. Not this. Fully compatible, but it's IaaS: you'd still patch and manage the OS and SQL Server yourself.
  • D. Not this. A NoSQL database. The application would need rewriting.

Keywords that point to it: "SQL Agent jobs""cross-database queries""managed (PaaS)""few code changes"

Question 7CoreA mobile game stores player profiles as JSON. Players are worldwide and need fast reads and writes close to them, in several regions. Which database fits?

The answer is B

Azure Cosmos DB is built for global apps: add regions with a click, use multi-region writes so each region accepts writes, get single-digit-millisecond reads near users, and choose a consistency level. JSON documents fit its NoSQL API naturally. Choose the partition key carefully (such as playerId) so load spreads evenly.

Every option, explained

  • A. Not this. Geo-replicas are read-only. Writes still go to one primary region, far from many players.
  • B. Correct. A globally distributed NoSQL database that replicates to any regions and can accept writes in each of them.
  • C. Not this. Single-region key-value storage, with no multi-region writes.
  • D. Not this. A relational database with one writable primary.

Keywords that point to it: "JSON""worldwide""reads and writes close to them"

Question 8IntermediateA SaaS company has 200 small customer databases. Each is busy at different, unpredictable times, and most are idle most of the day. How do you keep costs down?

The answer is D

An elastic pool gives a group of databases a shared budget of compute (vCores or eDTUs). Because the customers peak at different times, the pool can be sized for the combined load rather than the sum of the peaks. The classic signals are 'many databases', 'unpredictable' and 'different times'.

Every option, explained

  • A. Not this. You'd pay 200 times for peak capacity that's idle most of the time.
  • B. Not this. A big redesign that mixes customer data, and it doesn't address the usage pattern.
  • C. Not this. More management work, and you'd still size each VM for its peak.
  • D. Correct. Databases share one pool of compute, so their different peaks are absorbed together at a lower total cost.

Keywords that point to it: "200 small""different, unpredictable times""idle most of the day"

Question 9IntermediateEvery night you need to copy data from a SQL Server in your datacentre to Azure Data Lake Storage. The firewall team won't open any inbound ports. What do you use?

The answer is B

Azure Data Factory orchestrates data movement with pipelines and triggers (such as a nightly schedule). The self-hosted integration runtime is an agent you install on a machine in your network. It connects outbound over port 443, so no inbound firewall rule is needed, then reads private sources and moves data to Azure.

Every option, explained

  • A. Not this. The Azure integration runtime runs in Azure and can't reach a server behind your firewall without inbound access.
  • B. Correct. The self-hosted runtime makes only outbound HTTPS connections to Azure, reads the local SQL Server and copies to the lake.
  • C. Not this. Event Hubs ingests event streams. It isn't a scheduled copy tool for databases.
  • D. Not this. File Sync synchronises file shares, not database tables.

Keywords that point to it: "datacentre""every night""won't open any inbound ports"

Question 10IntermediateIn Cosmos DB, a user must always see their own updates immediately, but it's fine if other users see them a moment later. You want the lowest latency that meets this. Which consistency level?

The answer is C

Cosmos DB offers five levels from strongest to weakest: Strong, Bounded staleness, Session, Consistent prefix, Eventual. Session is the default and the most widely used. It guarantees 'read your own writes' (and monotonic reads) for each client session, while keeping the latency and cost close to the weaker levels.

Every option, explained

  • A. Not this. Guarantees everyone reads the latest write, but costs more latency and throughput than you need here.
  • B. Not this. Limits how far behind reads can be, for everyone. Stronger and slower than needed.
  • C. Correct. Within one client session, reads always reflect that session's own writes; other sessions may see them slightly later.
  • D. Not this. Fastest, but a user might not see their own update right away, which breaks the requirement.

Keywords that point to it: "see their own updates immediately""other users a moment later""lowest latency"

Question 1BasicYou need daily backups of 50 Azure VMs, kept for 30 days, so you can restore files or whole VMs after a mistake. What do you use?

The answer is B

Azure Backup protects VMs (and SQL, Azure Files, blobs and more) with policies that set the schedule and retention. Backups are stored in a Recovery Services vault, and you can restore individual files, disks or whole VMs. Backup protects against mistakes and corruption; replication (Site Recovery, GRS) protects against outages. You usually need both.

Every option, explained

  • A. Not this. Site Recovery replicates VMs for disaster recovery failover. It isn't designed for keeping 30 days of restore points.
  • B. Correct. Azure Backup takes scheduled backups, keeps them by policy and restores files, disks or whole VMs.
  • C. Not this. Replication copies mistakes too. If a file is deleted, the deletion is replicated.
  • D. Not this. Possible, but with no schedule, retention policy or central reporting, it's easy to miss VMs.

Keywords that point to it: "daily backups""kept for 30 days""after a mistake"

Question 2BasicIf the Central India region fails, a set of VMs must start in South India within an hour, with minimal data loss. What do you use?

The answer is D

Azure Site Recovery is Azure's disaster recovery service: continuous replication (RPO typically in seconds to minutes), recovery plans that start VMs in the right order, and test failovers into an isolated network so you can prove the plan works without affecting production.

Every option, explained

  • A. Not this. Daily backups could lose up to a day of data, and restoring many VMs takes time.
  • B. Not this. Zones protect against a datacentre failure within one region, not the loss of the whole region.
  • C. Not this. Availability sets spread VMs across racks in one datacentre.
  • D. Correct. Site Recovery continuously replicates VMs to another region and fails them over in order with a recovery plan.

Keywords that point to it: "region fails""within an hour""minimal data loss"

Question 3BasicA team has HTTP microservices packaged as containers. They don't want to manage servers or Kubernetes, and services should scale with traffic, down to zero when idle. What do you use?

Azure Container Apps runs containers on a managed, Kubernetes-based platform you never operate. Scaling rules (HTTP concurrency, queue length and others, through KEDA) add and remove replicas, down to zero. It also offers revisions for safe rollouts and Dapr integration for microservices.

  • C. Not this. That means managing VMs and the container runtime yourself.
  • D. Correct. Serverless containers with automatic scaling on HTTP traffic or events, including scale to zero.

Keywords that point to it: "containers""don't want to manage servers or Kubernetes""down to zero"

Question 4BasicWhenever a file is uploaded to a storage container, a short piece of C# code must create a thumbnail. You only want to pay when it runs. What do you use?

Question 5CoreOrders go from a web front end to a processing service. Orders for the same customer must be processed in order, duplicates must be ignored, and no order may be lost. What do you use?

The answer is A

Service Bus is for high-value business messages. Sessions guarantee first-in-first-out per session ID (for example the customer ID). Duplicate detection drops repeats within a time window. Messages stay until a consumer completes them, and failures go to a dead-letter queue. Signal words: 'order', 'in sequence', 'duplicates', 'transactions'.

Every option, explained

  • A. Correct. An enterprise broker with sessions (ordered per key), duplicate detection, transactions and dead-lettering.
  • B. Not this. Simple and cheap, but it has no ordering guarantee per customer and no duplicate detection.
  • C. Not this. Event Grid pushes notifications about things that happened. It isn't a durable, ordered work queue.
  • D. Not this. Built for high-volume telemetry streams, not individual business commands with per-message handling.

Keywords that point to it: "in order""duplicates must be ignored""no order may be lost"

Question 6CoreThousands of factory sensors send readings several times a second, millions of events a minute, which must feed real-time analytics and also be stored in a data lake. What do you use to ingest them?

  • C. Not this. Event Grid routes discrete events to handlers. It isn't a high-throughput stream with replay.
  • D. Not this. Throughput and features fall far short of a telemetry stream.

Question 7CoreWhen a new blob is created, three different systems should be notified immediately: a function, a webhook and a Logic App. Nothing should poll. What do you use?

The answer is C

Event Grid is the reactive glue of Azure. Sources such as Storage, resource groups or Key Vault publish events, and event subscriptions push them to handlers (Functions, webhooks, Logic Apps, queues) within moments, with filtering and retries. Think 'something happened, tell whoever cares'.

Every option, explained

  • B. Not this. A queue delivers each message to one consumer. Three systems would need extra plumbing.
  • C. Correct. Event routing with push delivery: one event source, many subscribers, filters and retries, with no polling.
  • D. Not this. That's polling, which the requirement rules out, and it adds delay.

Keywords that point to it: "notified immediately""three different systems""nothing should poll"

Question 8IntermediateAn application runs on VMs and needs a 99.99% VM connectivity SLA within one region. How do you deploy the VMs?

The answer is C

Know the three VM SLA steps: single VM (Premium SSD) 99.9%, availability set 99.95% (protects against rack and update failures), availability zones 99.99% (protects against a whole datacentre failing). Put a zone-redundant load balancer in front so traffic reaches healthy VMs.

Every option, explained

  • A. Not this. A single VM with Premium SSD has a 99.9% SLA.
  • B. Not this. Availability sets spread VMs across racks in one datacentre, for a 99.95% SLA.
  • C. Correct. VMs in two or more zones of a region carry a 99.99% connectivity SLA.
  • D. Not this. Dedicated hosts give you physical isolation, not higher availability.

Keywords that point to it: "99.99%""within one region"

Question 9IntermediateRansomware attackers often delete backups first. You must make sure that even a compromised backup administrator can't delete recovery points or reduce retention. What do you configure?

The answer is B

Ransomware-ready backups rely on three controls. Immutable vault: once locked, recovery points can't be deleted before they expire and retention can't be reduced. Always-on soft delete: deleted data is kept and the setting can't be switched off. Multi-user authorisation: critical operations need permission on a Resource Guard owned by a different team, ideally in another subscription or tenant.

Every option, explained

  • A. Not this. Helpful, but on its own it doesn't stop an admin from reducing retention, and the requirement covers more than deletion.
  • B. Correct. Locked immutability blocks early deletion; always-on soft delete can't be disabled; MUA needs a second team's approval for critical changes.
  • C. Not this. Then they can't do their job, and anyone else with the Contributor role could still delete backups.
  • D. Not this. The same compromised admin could delete that account too.

Keywords that point to it: "compromised""can't delete""reduce retention"

Question 10IntermediateYou'll publish APIs to external partners. You need API keys per partner, rate limits, versioning and a portal where partners can read documentation and test calls. What do you use?

The answer is C

API Management sits in front of your back-end APIs. The gateway enforces policies (authentication, rate limits, quotas, transformation, caching); products and subscriptions issue keys per consumer; versions and revisions let APIs evolve safely; and the developer portal gives partners documentation and a test console.

Every option, explained

  • A. Not this. A layer 7 load balancer with WAF. It has no API products, subscription keys or developer portal.
  • B. Not this. A global entry point and CDN. It doesn't manage API consumers or versions.
  • C. Correct. An API gateway plus management: products and subscription keys, policies such as rate limits, versions and revisions, and a developer portal.
  • D. Not this. A layer 4 TCP/UDP balancer. It can't see HTTP requests at all.

Keywords that point to it: "external partners""API keys""rate limits""versioning""portal"

Question 1BasicAdministrators need RDP and SSH access to VMs, but security forbids public IP addresses on VMs and open RDP or SSH ports to the internet. What do you use?

The answer is B

Azure Bastion is deployed into a dedicated subnet (AzureBastionSubnet) in the VNet. Admins connect through the Azure portal or a native client over HTTPS, and Bastion opens RDP or SSH to the VM's private IP. No public IPs on VMs, no exposed management ports, and access is controlled with RBAC.

Every option, explained

  • A. Not this. That still puts public IPs on VMs, and home IPs change.
  • B. Correct. A managed service that gives RDP and SSH through the portal (or native client) over TLS, with no public IPs on the VMs.
  • C. Not this. That publishes RDP to the internet through the firewall, which is exactly what's forbidden.
  • D. Not this. Site-to-site VPN connects networks, not individual admins, and is far more work than needed.

Keywords that point to it: "no public IP addresses""RDP and SSH"

Question 2BasicOnly the web subnet may reach the database subnet, and only on port 1433. All other traffic into the database subnet must be blocked. What do you use?

The answer is A

A network security group holds stateful allow and deny rules evaluated by priority (lower number first). Add an inbound rule allowing the web subnet (or an application security group) to TCP 1433, and rely on a deny rule for everything else. NSGs are free and are the first layer of segmentation; add Azure Firewall for central, application-aware control.

Every option, explained

  • A. Correct. NSGs filter traffic by source, destination, port and protocol with allow and deny rules, applied to subnets or NICs.
  • B. Not this. Routes decide where traffic goes next; they don't allow or block ports.
  • C. Not this. It protects public endpoints from volumetric attacks, not traffic between subnets.
  • D. Not this. A global entry point for HTTP traffic from the internet, not filtering inside a VNet.

Keywords that point to it: "Only the web subnet""port 1433""blocked"

Question 3BasicThe company needs a private, dedicated connection from its datacentre to Azure with predictable latency, and traffic must not cross the public internet. What do you use?

The answer is D

ExpressRoute gives a private connection via a provider or exchange, with bandwidths from 50 Mbps to 10 Gbps (100 Gbps with ExpressRoute Direct), an SLA and consistent latency. It isn't encrypted by default; add MACsec (on Direct) or run a VPN over it when encryption is required. A site-to-site VPN is a common backup path.

Every option, explained

  • A. Not this. Encrypted, but it travels over the public internet, so latency isn't predictable.
  • B. Not this. Connects individual computers, not a datacentre, and also uses the internet.
  • C. Not this. Peering connects Azure VNets to each other, not to on-premises.
  • D. Correct. A private circuit through a connectivity provider into Microsoft's network that doesn't use the public internet.

Keywords that point to it: "private, dedicated""predictable latency""must not cross the public internet"

Question 4BasicBefore migrating, you must discover 300 on-premises VMware VMs, check Azure readiness, get right-sized recommendations and see cost estimates. What do you use?

The answer is C

Azure Migrate is the hub for migration. Its lightweight appliance discovers VMware, Hyper-V or physical servers, collects performance data and maps dependencies. Assessments then report Azure readiness, recommended sizes based on real usage, and monthly cost estimates, and the business case compares on-premises and Azure costs.

Every option, explained

  • A. Not this. Site Recovery replicates machines, but it doesn't assess readiness or size and price them.
  • B. Not this. Advisor recommends improvements for resources already in Azure.
  • C. Correct. The Azure Migrate appliance discovers VMs and collects performance data, and assessments give readiness, sizing and cost.
  • D. Not this. Arc manages servers that stay outside Azure. It isn't a migration assessment tool.

Keywords that point to it: "discover""readiness""right-sized""cost estimates"

Question 5CoreAn app in a VNet, and servers on-premises connected by VPN, must reach Azure SQL Database over a private IP address. The database's public access will be disabled. What do you use?

The answer is B

A private endpoint (Azure Private Link) puts a network interface with a private IP for the PaaS resource into your subnet. Traffic stays on private paths, including from on-premises over VPN or ExpressRoute. The critical part is DNS: the privatelink.database.windows.net zone must resolve the server name to the private IP, using a DNS Private Resolver or forwarders for on-premises clients.

Every option, explained

  • A. Not this. A service endpoint keeps the database on its public address and only works from that VNet. On-premises servers can't use it.
  • B. Correct. It gives the database a private IP in your VNet, reachable from peered networks and on-premises, so public access can be turned off.
  • C. Not this. Firewall rules control public access. They don't give the database a private IP.
  • D. Not this. NSGs filter traffic. They don't change how the database is reached.

Keywords that point to it: "private IP address""on-premises""public access will be disabled"

Question 6CoreA public web application runs in two regions. You need one global entry point with path-based routing, a web application firewall, caching of static content and fast failover if a region fails. What do you use?

The answer is D

Azure Front Door terminates users' connections at the nearest Microsoft edge location, then routes requests to the best healthy origin. It offers path-based routing, WAF, caching and compression, TLS offload, and very fast failover because it doesn't depend on DNS caches. Use Application Gateway inside a region, and Traffic Manager for non-HTTP or DNS-level routing.

Every option, explained

  • A. Not this. DNS-based routing only. It doesn't inspect HTTP, so no path routing, WAF or caching, and failover waits for DNS caches to expire.
  • B. Not this. It has layer 7 features and a WAF, but it's regional and can't be the global front door across two regions.
  • C. Not this. Layer 4 only. It has no understanding of paths or HTTP.
  • D. Correct. A global layer 7 entry point at Microsoft's edge with path routing, WAF, caching and health-probe-based failover.

Keywords that point to it: "two regions""global entry point""path-based routing""web application firewall""fast failover"

Question 7CoreAn internal line-of-business web app runs on VMs in one region. You need layer 7 load balancing with TLS termination, URL path routing and a WAF, reachable only from the corporate network. What do you use?

The answer is A

Application Gateway is the regional HTTP(S) load balancer: TLS termination, URL path and host-based routing, session affinity, autoscaling (v2) and an integrated WAF. With a private frontend IP it serves internal apps reachable over VPN or ExpressRoute. A useful way to remember the four: global plus HTTP → Front Door; regional plus HTTP → Application Gateway; regional TCP/UDP → Load Balancer; DNS → Traffic Manager.

Every option, explained

  • A. Correct. A regional layer 7 load balancer with TLS termination, path routing and WAF, deployable with a private IP inside the VNet.
  • B. Not this. Front Door is a global, internet-facing service. The app must be internal only.
  • C. Not this. Private, but layer 4 only: no TLS termination, path routing or WAF.
  • D. Not this. DNS-based and global. It doesn't load-balance HTTP inside a VNet.

Keywords that point to it: "internal""one region""layer 7""WAF""only from the corporate network"

Question 8IntermediateYou must move 100 TB of files to Azure within three weeks. The office internet link is 50 Mbps and is used by everyone. What do you use?

The answer is B

Always do the arithmetic. 100 TB = 800,000,000 megabits; ÷ 50 Mbps = 16 million seconds ≈ 185 days at full speed. When the network can't finish in time, use Azure Data Box: Microsoft ships a rugged device, you copy data at local network speed, ship it back, and it's uploaded to Blob or Azure Files. Use online tools (AzCopy, Storage Mover, File Sync) for the changes afterwards.

Every option, explained

  • A. Not this. 100 TB at 50 Mbps takes about 185 days even with the link to yourself.
  • B. Correct. An offline transfer device: copy locally, ship it to Microsoft, and the data is uploaded into your storage account, typically in one to two weeks.
  • C. Not this. A good online migration tool, but it's limited by the same 50 Mbps link.
  • D. Not this. Provisioning often takes weeks, it costs every month, and it's overkill for a one-time move.

Keywords that point to it: "100 TB""within three weeks""50 Mbps""used by everyone"

Question 9IntermediateIn a hub-and-spoke network, spoke VNets are peered only to the hub. Spokes must talk to each other, and all spoke-to-spoke traffic must be inspected centrally. What do you do?

The answer is D

VNet peering is not transitive: spoke A peered to the hub and spoke B peered to the hub doesn't connect A and B. Put an Azure Firewall (or a network virtual appliance) in the hub, and add user-defined routes in each spoke that send other spokes' address ranges to the firewall's private IP. Virtual WAN with secured hubs can automate this routing.

Every option, explained

  • A. Not this. Gateway transit lets spokes use the hub's VPN or ExpressRoute gateway. It doesn't route traffic between spokes.
  • B. Not this. Spokes could talk, but traffic would bypass central inspection, and the mesh grows quickly.
  • C. Not this. NSGs filter; they can't create the missing route between spokes.
  • D. Correct. Peering isn't transitive, so routes force spoke traffic through the firewall, which inspects and forwards it.

Keywords that point to it: "peered only to the hub""talk to each other""inspected centrally"

Question 10IntermediateA 3 TB SQL Server 2019 database must move to Azure SQL Managed Instance with only a few minutes of downtime at cutover. What do you use?

The answer is A

For minimal downtime, keep the target in sync while the source stays live. The Managed Instance link replicates from SQL Server (2016 SP3 and later) to SQL Managed Instance in near real time using distributed availability groups. Azure Database Migration Service in online mode does continuous log restore. At cutover you stop writes, let the last changes arrive, and switch the connection string, usually within minutes.

Every option, explained

  • A. Correct. The database stays in sync while the application keeps running; cutover is a short, planned switch.
  • B. Not this. An offline method: the database must stop changing during export and import, which takes hours at 3 TB.
  • C. Not this. Also offline. Any changes after the backup are lost unless you stop the application for the whole copy.
  • D. Not this. Data Box moves files offline. It doesn't keep a live database in sync.

Keywords that point to it: "3 TB""only a few minutes of downtime"
